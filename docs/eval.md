# Оценка поиска: fts и vector

Retrieval evaluation report: keyword search vs vector search, 19 questions, k=5

## Условия

- Дата прогона: 22 октября 2026.
- Модель эмбеддингов: bge-m3.
- Данные: 70 синтетических сообщений.
- Вопросы: из 20 вопросов в `data/questions.json` у 19 есть эталон (`gold_ids`), один без эталона пропущен.
- Параметр поиска: k=5.
- Повторяемость: `make eval` запускали дважды, цифры и списки промахов совпали. Отличалось только форматирование таблицы.
- Метрики: hit@5 — доля вопросов, у которых хотя бы одно эталонное сообщение попало в топ-5; MRR@5 — средний обратный ранг первого эталонного сообщения в топ-5 (0, если его там нет).

## Результаты

| метод  | hit@5 | MRR@5 | число вопросов |
| ------ | ----- | ----- | -------------- |
| fts    | 0.579 | 0.381 | 19             |
| vector | 0.737 | 0.561 | 19             |

Исходный вывод: [eval-baseline.md](eval-baseline.md).

## Ограничения

- Всего 19 вопросов: один вопрос — это примерно 5 процентных пунктов.
- Вопросы писал тот же автор, что и данные.
- Данные синтетические.
- MRR@5 считается только по топ-5: ранги за пределами пятого места не учитываются.
- Эталон может быть неполным (см. вопрос 1 и сообщение 22).

## Выводы

- vector лучше fts на 3 вопроса из 19 (hit@5 0.737 против 0.579). При таком размере выборки это сигнал, а не доказательство.
- Основная проблема обоих методов: находится нужная история, но не то сообщение, которое отвечает на вопрос (симптом вместо причины или решения).
- Следующий шаг: гибридный поиск (fts + vector) и добавление к найденному сообщению соседних сообщений из того же разговора.
